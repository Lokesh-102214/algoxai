# Visual design principles

## Interaction before spectacle

Use 3D only when position, depth, rotation, or spatial grouping adds explanatory value. A 2D view is better when it is clearer.

## One question per scene

A learner should be able to answer what the visualizer demonstrates in one sentence. Add controls only when they help answer that question.

## State must be legible

Show the active operation, what changed, and what happens next. Do not rely on colour alone; pair colour with text or shape where practical.

## Progressive depth

The default state should invite exploration. Advanced controls, custom inputs, and implementation details should be available without blocking a first-time user.

## Accessible by design

Support keyboard-accessible controls, respect reduced-motion preferences where possible, and provide a textual explanation of events in a scene.
